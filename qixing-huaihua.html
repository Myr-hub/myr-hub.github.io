七星怀化：同名玩法与房间标识

13项地区玩法，结合字牌配置与桌台列表讨论房间身份和列表更新。

版本内容界面配图独立示例技术交流

怀化版本的玩法组合

怀化版本包含13项玩法：麻将6项，为急速8张麻将、长沙麻将、转转麻将、红中麻将、怀化麻将和靖州麻将；字牌4项，为红拐弯、沅陵跑胡子、溆浦跑胡子和溆浦老牌；扑克3项，为11张跑得快、欢乐斗地主和跑得快。

地区内容集中在怀化、靖州的麻将，以及沅陵、溆浦等字牌入口。它们可以共享分类导航和房间列表，但不能仅凭名称归入同一套规则配置。

字牌配置与同名桌台

红拐弯配置页提供人数、局数、发牌和名堂等选项。庭院桌台页则把玩法名称与桌台序号同时展示，其中1号与6号都显示怀化麻将。同名玩法可以对应多个房间，因此列表中的玩法名称应作为展示字段，房间标识应单独保存。

规则图为AI整理的截图局部；桌台图仅压缩。群组ID60175与桌台序号保留原状，没有当作个人账号替换。元宝、房费和积分等标签保留，本文不据此推断兑换机制或宣称纯房卡模式。

用群组与房间标识定位桌台

房间列表需要区分“玩什么”和“进入哪一桌”。如果用“怀化麻将”作为列表唯一键，同名桌台可能互相覆盖；如果房间编号仅在群组内唯一，还应把群组标识纳入索引。是否具备全局唯一房间ID，应由接口约定明确。

下面是独立编写的复合键示例，假设调用方提供群组内唯一的房间ID。它不是原工程代码，不根据画面中的桌台序号推断实际接口。使用数组序列化可以避免直接以冒号拼接产生分隔符歧义。

export function roomKey(room) {
  if (!room || typeof room.groupId !== 'string' || !room.groupId.trim()
      || typeof room.roomId !== 'string' || !room.roomId.trim())
    throw new TypeError('Group and room IDs required');
  return JSON.stringify([room.groupId.trim(), room.roomId.trim()]);
}

独立房间键示例通过10项断言，覆盖同群不同桌、不同群同号、分隔符、空白与无效输入。这个键只用于界面索引，不能作为访问授权凭据；加入房间的权限由服务端独立检查。

刷新列表时，可以按稳定房间键更新人数和状态，而保留用户正在查看的详情。显示名称更改不应导致房间身份变化；关闭后重新创建的房间也不应误用旧记录。
